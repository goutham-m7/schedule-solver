# v0.2 technical design

## Problem and constraints
Turn the existing offline optimizer into a reusable calendar tool while preserving strict validation, honest optimality claims and independent greedy comparison. Local main commits only; no remote actions, employer inputs or external services.

## Chosen interfaces and flow
Calendar import accepts an optional Period horizon, required for recurrence, and expands with python-dateutil in DTSTART local time before converting occurrences to UTC. EXDATE and RDATE are set operations. Skip nonexistent recurrence wall times; choose the first fold for ambiguous local times. All-day durations use local dates. Reject detached RECURRENCE-ID and EXRULE rather than silently misreading them. Limit candidate expansion to 10,000 generated instances per event, including historical traversal; report budget exhaustion.

`resolve(workload, previous, time_limit)` accepts the edited complete workload and a list of earlier Meeting assignments. Missing requests mean cancellation; new requests mean addition; altered request windows force moves. Validate previous structural integrity, but allow formerly valid assignments to violate edited calendars. The CP-SAT priority pass stays first. A second pass counts an existing meeting changed if its start, end or attendee set differs or it is dropped. Existing secondary passes follow. This avoids a weighted sum trading priority for stability. It rebuilds the model, not an incremental native CP-SAT session. A baseline remains the safe fallback; no stability optimum is claimed if its pass times out.

Small insertion diagnostics exhaust subsets of the entire label universe, not merely the initial core, in increasing cardinality up to the deletion-core size. A 12-label ceiling bounds combinatorial work; larger problems retain inclusion minimality. Results identify the guarantee. Frozen-schedule semantics do not change.

Calendar export validates result assignments and serializes UTC VEVENTs using icalendar. UIDs derive from request IDs, with no private email inference. Attendee IDs are stored as X-SCHEDULE-ATTENDEES rather than fabricated mailto addresses. CLI --ics and HTTP /export-ics share the serializer.

Benchmark generators have independent pods and cross-pod shared specialist skills. Curves run greedy once and CP-SAT at each supplied budget, record priority bound/status, full metrics and runtime versions. Limits increase to 500 people / 1200 requests.

## Alternatives and tradeoffs
A recurrence-specific dependency provides overrides but adds a larger contract; dateutil is already a dependency transitively and is made explicit. A mutable session API requires storage and lifecycle management; complete edited workload plus previous assignments is reproducible and stateless. Weighted stability would compromise primary priorities; a lexicographic pass is explicit. Unbounded minimum conflicts are exponential; capped exhaustive search has an honest fallback. UTC export avoids custom VTIMEZONE and client-specific local-time ambiguity.

## Failure behavior and security
Malformed recurrence, unsupported overrides, missing horizons and exhausted budgets fail closed. HTTP validation errors return 422; diagnostic timeouts retain 503. The loopback API remains unauthenticated and is not production-ready. Calendar serialization uses the library escaping/folding rules and never interprets IDs as network addresses. No network activity is needed by any new feature.

## Migration and rollout
New fields have compatible defaults. Nonrecurring import remains callable without a horizon. CLI import supplies the workload horizon. Existing solve defaults retain their objectives. Schema limits expand but do not relax time, identity or reference validation. Version 0.2.0 distributions are built, never published.

## Verification plan
Each roadmap item has behavioral tests at its public Python/CLI/HTTP boundary; no internal mocks. Real OR-Tools, dateutil and icalendar execute locally. No real calendar provider interoperability or arbitrary dense-graph scalability claims are made. Final evidence comes from a fresh local clone: locked installation, full tests, Ruff, demo, benchmarks and isolated wheel installation.
